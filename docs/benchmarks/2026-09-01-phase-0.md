# Phase 0 performance baseline

- Date: 2026-09-01
- Go: 1.26.6
- OS/architecture: Linux amd64
- CPU: AMD Ryzen 7 5800H
- Command: `go test -run '^$' -bench . -benchmem ./internal/dialects/mysql`

| Benchmark | Time | Bytes/op | Allocations/op |
| --- | ---: | ---: | ---: |
| PolicyValidate | 20,502 ns | 6,205 | 86 |
| MetadataCacheHit | 121.6 ns | 72 | 2 |
| ResponseBudget, 100 rows | 67,811 ns | 52,383 | 704 |

These are local microbenchmark baselines. They do not represent database
latency or a production service-level objective. Results must be compared on
the same class of runner; CI should retain raw benchmark output for statistical
comparison.

The metadata-cache benchmark is a warm hit and includes defensive cloning. The
response-budget benchmark includes cloning a 100-row result and exact JSON-size
verification.

## Verification at this phase

- `go test ./...`: pass
- `go vet ./...`: pass
- `go test -race ./internal/admission ./internal/dialects/mysql`: pass

Real-MySQL latency, cancellation, pool and soak measurements require a
disposable MySQL 8 service and are intentionally not fabricated in this local
baseline.
